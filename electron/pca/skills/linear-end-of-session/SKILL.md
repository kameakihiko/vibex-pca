# Linear end of session

Use this skill when a work session ends. It records the result in the Linear issue, so the next person can continue without the chat.

## Before you write

1. Find the issue key in the branch name, the commit messages or the person's words. If you cannot find one, ask the person for it. Do not guess.
2. Check that a Linear tool is available in this session. If it is not, give the person the text below to paste. Do not sign in for them.
3. Read the current issue first. Add to it; do not replace what is there.

## What goes in the update

Write short sentences. One fact in each sentence.

- **Done:** what changed, in plain words, with the names of the files or documents.
- **Checked:** what you ran or read to prove it, with the counts as "N of M".
- **Not done:** what you did not do, and why.
- **Next:** one step, and who does it by role.
- **Where:** the branch, the pull request, or the folder.

## Personal data rule

Linear is a third-party service. Do not write any of these in it:

- names, phone numbers, e-mail addresses or chat ids of clients, students or staff;
- amounts or balances that belong to a client;
- passwords, keys, tokens or the content of a credential file.

Use roles ("the client owner", "a consultant"), document numbers and system ids instead.

## After you write

1. Read the issue back. Check that the update is there and that it holds none of the data above.
2. Give the person the issue key and one line that says what you wrote.
3. If the work is finished and the person agrees, set the status they ask for. Do not close an issue on your own.
